## Summary

The Sub-Store companion plugin today is a Go shell around a 1.27 MB bundle of upstream JavaScript that parses, transforms and produces every subscription on a QuickJS runtime, at about one millisecond per node, with the operator's regexes on a backtracking engine and a script sandbox that is not closed. It reaches the fleet only through a bare list of share links that carry each line owner's credential, so every holder of a share token for a fleet record authenticates as the line owner.

This design rebuilds the plugin as a Go pipeline over one typed node model. Parsing, normalisation, every non-script operator and every client producer become Go. QuickJS runs only operator-authored scripts, one fresh isolate per invocation, behind a small shim rather than the upstream bundle. Fleet subscriptions become an identity-free selection over a credential-free line catalogue; each share names the identity it serves, and core injects that identity's credential after the chain has run and after core has validated every planned node against the catalogue, before a zero-host-call step produces the document. No method that runs scripts or has network ever sees a fleet credential. The three contracts core calls today (`fetch`, `render`, `convert`) are extended, never replaced, so share serving, the decoy, the content-addressed cache and identity links keep working through every slice. The upstream bundle is demoted to a conformance oracle that gives each client target a measurable number; it leaves the signed artifact when every target passes.

The first slice is a sandbox hotfix on the current plugin plus the platform additions the rebuild needs; the rest ships in six slices behind unchanged contracts. The companion boundary of design 15 and the runtime doctrine of design 18 (platform paths in Go, QuickJS for user scripts only) both hold.

## What the operator asked (2026-10-08)

Deeply optimise the Sub-Store plugin's own functionality, for extreme performance and architecture; the UI need not match upstream, but every function must exist; reimplementing is allowed and expected, with thorough tests and optimisation, especially automatic integration with the platform's existing Lines, parsing and applying user-defined scripts, node filtering, the final exported share links, and security. Free Cloudflare products are acceptable where they genuinely improve the architecture; nothing that costs money.

## Facts this design rests on

1. **The sandbox is not closed.** Scripts running on the pinned QuickJS build can reach runtime globals and a mounted directory that they should not see, and the plugin does not remove them (`sg/substore_engine.go:438-447,623-631`). Established by reading; the first slice turns it into a test and closes it on both the plugin and the server side. The mechanism and the remaining file references are withheld from this document until that slice is installed.
2. **QuickJS is the cost, measured.** On a scratch copy of the plugin at 7157401 (laptop, go1.26.1, bundle 2.36.22), the warm path renders about 0.9 ms per node, linear in node count and the same for URI, ClashMeta and sing-box; four non-script operators do not change it; the isolated path adds 683 ms of boot, most of it wasm module compilation. A Go baseline on the same input is 1.7 ms at 1000 nodes and 16 ms at 10000, roughly 500 times less. The warm runtime holds 44 MiB idle and reached 222 MiB after a 10000-node render.
3. **Size bounds bite before the clock.** A 10000-node URI list is 2.46 MB against `MaxSubscriptionRawBytes` of 1 MiB; its sing-box output is 6.29 MB and ClashMeta 4.33 MB against `MaxSubscriptionResponseBytes` of 4 MiB and the 6 MiB render stdout budget (`sdk/model/subscription_source_manifest.go:21-26`). At 3000 nodes everything fits.
4. **Core already owns the serve path.** Tokens are 32-byte CSPRNG values sealed at rest and resolved through an HMAC index (`srv/server_subscription_share_api.go:511-513`, `store/subscription_share.go:62-77`); every refusal is one decoy (`srv/subscription_decoy.go:21-79`); content type and headers are core-chosen (`srv/server_subscription_share.go:191-226`); bodies are cached 30 minutes with hash-extend (`:145-172`); any committed fleet write expires every plugin share body because core cannot tell which records read the fleet (`srv/share_fleet_changes.go:9-46`, the wanted method at `:26-28`).
5. **Core already renders per-identity entries.** Identity links build one entry per bound line from a credential-free template plus the identity's credential, list excluded lines with a reason, and compute `Subscription-Userinfo` from policy (`srv/identity_link.go:204-308,364-447`; templates `srv/line_client_templates.go:82-116`). Only URI and V2Ray are written by core; other targets call the plugin's `convert` with `{uris, target, options}` (`:724-755`). The core-backed service `latticenet.sub-store/shares` lists this plugin's shares and reveals one share's URL only through the step-up reveal gate (`srv/server_substore_plugins.go:26-124`).
6. **The fleet reaches the plugin as bare strings.** `host_access` grants only `vpn-core/nodes.export` and `subscription-sources.{compose,graph_options}`. `export` returns link strings with no ids and, for discovered lines, the owner's `share_url` (`srv/server_vpncore.go:534-620`, `:607-616`). The Line read model (`srv/lines.go:24-116`), `NodeGeo`, `MachineProfile`, groups, tags, DDNS domains and usage all exist and none is reachable from the plugin. `vpn-core-graph` records compose one identity through ordered committed chain roots, vless Reality only.
7. **Runtime limits.** Pooled workers per plugin default to one plus one overflow (`plg/system_runner.go:40-46`); 30 s per call; 4 MiB per host-call result; host HTTP responses capped at 256 KiB while the plugin advertises 8 MiB (`srv/plugin_host.go:21-22`); KV has `get` and `put` only, plaintext, with a linear bucket scan per get (`srv/plugin_host.go:192-203`); the plugin keeps every record in one 1 MiB document (`sg/subscription_store.go:18-25`). The plugin UI runs in an opaque-origin iframe with `connect-src 'none'` and can reach the backend only through plugin methods and the core-backed services its manifest declares.
8. **Upstream.** AGPL-3.0, no authentication, scripts through `new Function` with Node `require`, local file reads from URLs and `_ca` fields, `external` exec entries emitted for Surge for Mac, user regex on a backtracking engine (upstream study, section 2). Its pipeline (download, preprocess, parse, normalise, process, produce) and its 105-item capability checklist are the acceptance baseline. The embedded bundle is 68 commits behind upstream head.
9. **The probe is not built.** Design 27 proposes on-demand tests with a history keyed by config hash, abuse limits of 4 concurrent and 120 per hour per principal, and no join to `line_uuid` yet. Anything here that reads probe data reads a cached verdict that design 27's P2 slice writes, never a live probe on the serve path.

## Goals and non-goals

Goals. Every row of the 105-item checklist exists, natively or by a stated equivalent, and the companion slice plan's coverage table names each row's mode (native, substitute with the reason, or not applicable) so the tally the operator approves is accurate. Scriptless renders in Go at tens of milliseconds for thousands of nodes. Fleet subscriptions selected over Lines and fleet metadata, bound per identity on the share, with exclusion reasons and policy-derived traffic headers. Scripts run in a bounded isolate with the upstream-compatible API surface the community targets. Share links keep core's token model, decoy and cache. A published conformance number per client target. Secrets in the encrypted secret store, masked everywhere, revealed only through an audited step-up, never in logs or URLs. An operator surface that is dense, navigable, trilingual, keyboard-operable, and works at 1440 and 375. Every UI action is a plugin method or a declared core-backed service an agent can call.

Non-goals. Copying upstream code. Pixel parity with the upstream front end. Moving composition into the server or into vpn-core (design 15 D4/D5 stand). A Node runtime (design 18 D6). Gist or GitLab clients. Use-count expiry. Custom share tokens. MaxMind databases and IP-API (fleet geo comes from `NodeGeo`; provider geo comes from the probe on demand). Startup restore from a data URL. Caching or terminating `/sub/` at a third party. A backtracking regex engine, even time-limited.

## Architecture

### Process model

Nothing changes in where things run. Core keeps the public route, token resolution, rate limit, decoy, audit, caches and header policy. The plugin keeps running as a persistent `stdio-json-v2` worker pool behind the broker, with signed per-method budgets. The companion boundary is the security feature: hostile internet content is parsed in the least privileged process, behind the SSRF guard that re-checks at dial time and on every redirect (`plg/broker.go:664-684`, `internal/outbound/outbound.go:54-100`), with scopes bound per method.

```
client ── GET /sub/<slug>/<token> ──► core: token, slug, format, rate limit, decoy
                                        │ snapshot (lazy refresh ≤ 30 min)
                                        ▼
                             plugin fetch ──► provider over http.do, or the line catalogue over rpc.call
                                        │ compact canonical model plus retained raw, source_version
                                        ▼
                             plugin render ──► Go pipeline; scripts in a fresh isolate
                                        │ provider record: document            fleet-bound record: plan
                                        ▼                                       ▼
                             core: headers, cache, ETag, gzip        core: validate plan against the catalogue,
                                                                     bind the share's identity, exclusions, userinfo
                                                                                 │
                                                                                 ▼
                                                                     plugin convert (zero host calls) ──► document

                             plugin depends_on (method, transitive) ──► core expiry index for fleet writes
```

Two things do change. The warm QuickJS runtime disappears once the Tier 1 producers are native, because scriptless chains no longer need JavaScript at all. And a fleet-bound record's `render` returns a plan instead of a document, so the credential is bound in core and the only plugin method that ever holds it is `convert`, which has no network, no store and no script network by its signed budget.

### Fleet-bound documents

A record is fleet-bound when any source in its transitive closure is a `fleet` record: a fleet record itself, a collection with a fleet member, a provider record whose chain pulls a fleet record through Add Proxies From Subscription, or a file or mihomo config whose node source is any of those. `depends_on` reports exactly that closure. Every fleet-bound record renders as a plan, never as a document, and the rules below hold for every shape:

- Fleet rows carry synthetic credentials that are unique placeholder strings per line and credential field (`LATTICE-SYN-<line_uuid>-<field>-<random>`), generated per render. They are not valid credentials anywhere.
- Provider nodes inside a fleet-bound document are materialised in full in the plan (provider credentials are the operator's own provider content, not fleet credentials, and already live in the snapshot).
- The chain, including collection-level steps, scripts with network and Add Proxies From Subscription, runs before binding over placeholders.
- A typed-node plan (fleet records, collections, provider records with pulled fleet nodes) carries the ordered node list with each fleet node's `line_uuid`. Core validates, binds and calls `convert` with typed nodes.
- A document plan (file and mihomo config records, where `main(config)` and processors operate on YAML text) carries the produced document with placeholders still inside, plus the typed fleet nodes it was produced from. Core validates the typed nodes, then requires that each placeholder occurs in the document exactly as many times as that line has validated clones; a placeholder a script copied into a name or a comment breaks the count and the document is refused with `placeholder_count`. `convert` then substitutes the bound credentials textually, with zero host calls.
- A script cannot call `produceArtifact` on a fleet-bound record; the call fails with a stated reason, because no credential may enter a script. A script on a fleet-bound record sees fleet nodes with placeholders, which is enough to rename, sort, filter and group them.
- Artifacts of fleet-bound records are rendered by core through the same path as a share, encrypted in core, and handed to the plugin's `publish` as ciphertext only. The plaintext opt-in for artifacts exists only for records that are not fleet-bound. Backups contain selections and chains, never credentials, because records are identity-free.

### Pipeline stages

A record's chain compiles once per revision into a typed plan with six stages.

1. **Source.** `remote` (one or more URLs fetched in parallel over `http.do`, each with fragment options), `local` (pasted text), `fleet` (an identity-free structured selection over the line catalogue; the identity is a property of the share, or of the operator's choice in preview), `collection` (members and tag members, each with its own chain), `file` (a document with a node source). The legacy `vpn-core` and `vpn-core-graph` sources keep working until migrated (section "Migration").
2. **Preprocess.** HTML discard, Clash and mihomo YAML to one object per line, Base64 (known schemes and fallback), SSD, full-profile section extraction. Size-bounded and fuzzed.
3. **Parse and normalise.** URI family (ss, ssr, vmess in all variants, vless with every transport, Reality, xhttp and ECH, trojan, hysteria, hysteria2, tuic, anytls, wireguard, socks, socks5, socks5+tls, http, https), Clash and mihomo objects with every mihomo type, Surge, Loon and Quantumult X lines. Normalisation produces the typed model (next section): SNI and Host pinning, port hopping, shadow-tls, TUIC and WireGuard defaults, certificate fingerprint. Hostile-content rules apply here: `external` and exec-shaped proxies are dropped from remote and pasted input, `_`-prefixed and `_ca`-style fields are stripped, nodes with invalid UUIDs are warned and dropped as upstream does.
4. **Process.** The operator chain. Filters are predicates over the slice; operators mutate in place; regexes compile once per chain with Go `regexp`, which is RE2 and cannot backtrack catastrophically. Script Operator and Script Filter steps hand the model to a fresh isolate and take it back. For fleet records the leading run of structured filter steps is pushed into the catalogue query and the rest runs here.
5. **Bind (fleet-bound records only, in core).** Core first validates every node in the plan against the catalogue rows it holds for the record's snapshot, then binds. Validation, per node: (a) the node's `line_uuid` is in the snapshot's selected set and the share's identity is bound to that line; (b) type, protocol, transport, security and the location of the credential field equal the line's template, and the credential field still carries the unmodified placeholder; only a named mutable set may differ from the template (`name`, `udp`, `tfo`, `mptcp`, `ip-version`, `block-quic`, `ecn`, `alpn`, `client-fingerprint`, `skip-cert-verify` with a logged warning, and the `script` map); (c) `server` is the template host, the line's `provider_edge`, one of its verified DDNS names, or one of the addresses the catalogue lists for the line (so Resolve Domain still works), and `port` is the template port or inside the line's port-hopping range; (d) anything else is excluded with `plan_rejected:<field>` and shown in the Fleet view. Several nodes may carry one `line_uuid` (Handle Duplicate in rename mode, cloning scripts), at most four per line, each validated. A node without a `line_uuid` in a fleet position is excluded with `no_line`, so a script cannot inject a foreign node into a fleet document. After validation each placeholder is replaced by the identity's real credential through the existing template and credential paths; lines whose template is lossy, whose service is down, whose node has not applied the credential, whose chain path is drifted or busy, whose usage rule or probe rule (both opt-in per record) fails, are listed as excluded with a reason; `Subscription-Userinfo` comes from the identity's policy.
6. **Produce.** One Go producer per target writes into one buffer; Response Transformer steps run on the produced body in a no-network isolate; the zero-node refusal runs in the plugin and again in core.

### The typed node model

One Go struct family with the same field set as upstream's parsed node, close to mihomo's proxy schema, written from the behaviour specification described under "Licensing": identity (`name`, `type`, `server`, `port`), credentials per protocol, `tls`, `sni`, `skip-cert-verify`, `tls-fingerprint`, `client-fingerprint`, `alpn`, `reality-opts`, `ech-opts`, transport (`network`, `ws-opts`, `grpc-opts`, `h2-opts`, `http-opts`, `httpupgrade-opts`, `xhttp-opts`), protocol specifics (`flow`, `packet-encoding`, `encryption`, `cipher`, `plugin` and `plugin-opts`, `obfs`, `ports`, `hop-interval`, `congestion-controller`, `udp-relay-mode`, `reduce-rtt`, `alterId`, `aead`, WireGuard peers, `private-key`, `reserved`, `mtu`), behaviour (`udp`, `tfo`, `mptcp`, `smux`, `ip-version`, `dialer-proxy`), Lattice fields for fleet lines (`line_uuid`, `line_hash_id`, `node_id`, geo, chain block, tags, groups, probe block, addresses) and an `extra` map that carries unknown keys through untouched, so upstream's new mihomo types (the September additions, for example) parse and reproduce without a schema change. Underscore fields set by scripts live in a separate `script` map that producers never emit. Every field has a size bound; empty fields are omitted on the wire so a 4096-node plan stays inside its budget. The model is the contract for operators, scripts (serialised to the same JSON shape upstream scripts see) and producers.

### Where scripts run and their sandbox

Only Script Operator, Script Filter, file processors, mihomo override scripts and Response Transformers run JavaScript. Each invocation gets a fresh QuickJS isolate seeded from the shim's precompiled bytecode, with the compiled wasm module cached in-process so boot is isolate creation rather than compilation: 128 MiB memory, 8 MiB stack, no runtime globals or native timers (removed before any code runs; an engine-controlled `setTimeout` is reinstalled), an empty read-only directory as the only mounted path, and exactly one host function for HTTP, bound to the current invocation and detached when it ends.

Budgets are per render, not per step. The method budget is 30 s; the Go stages reserve 5 s; every script step in a chain (operators, filters, file processors, transformers) shares one 20 s script budget, decremented as steps run, and no single step gets more than 15 s of what remains. Script HTTP is 8 calls per render in total, 256 KiB per response, 4 MiB in total, 5 s per call and 12 s in total, counted inside the calling step's time. Steps run serially, so at most one isolate is alive per render. Network is off by default per record, enabled per record with a host allowlist, granted only in `render` and `publish` as today (`sg/script_network_policy.go:35-42`), and every call is written to the processing log and to `log.write` with URL and header redaction. Scripts on fleet-bound records run before binding, over placeholders; Response Transformers on fleet-bound records run after binding, inside `convert`, where no network exists, and there they may only set the allow-listed response headers: a body write is discarded and recorded in the processing log. A rewrite after binding could move a line to a host the script controls, which core cannot catch because it does not parse every target format; upstream uses transformers almost entirely for headers, and body changes on fleet-bound records belong in the pre-bind steps, which run over placeholders and are validated. Core screens every header value for the share identity's credentials before serving it.

Inside `convert` the script surface is the no-host-call subset, and the editor says so: `$content` and the response body, `$options` with `_req` and the allow-listed `_res.headers`, `$arguments`, `context.source`, `context.env` and `targetPlatform`, `ProxyUtils.parse`, `produce`, `yaml`, `Base64`, flag, IP, `JSON5` and `hex_md5` helpers, `$substore.info` and `$substore.error` (buffered in the `convert` reply and written to the processing log by core). Absent there, and refused with a stated reason: `$substore.http`, `doh`, `scriptResourceCache`, `$persistentStore`, `produceArtifact`, `$substore.notify`, `$substore.wait`. Saving a Response Transformer on a fleet-bound record runs a static identifier check and flags any of those names before the step ever runs.

Remote script links are pinned. Saving a link fetches it and stores its SHA-256 and a module copy; the editor shows the digest. On every refetch a changed digest puts the record into a `script_changed` state. The default policy, `hold`, keeps running the pinned copy, shows a diff, and waits for the operator to accept; the per-link opt-in `follow` runs the new version, logs the change and notifies through the record's policy. A link is never run with network grants at a digest the operator has not seen.

### Caching and invalidation

Core keeps the durable caches: the 30-minute body cache with hash-extend, the 6-hour identity conversion cache keyed by entry digest (which is what makes one record serving many identities cheap), stale-if-error, `ETag` and 304, gzip. The plugin adds an in-process LRU bounded by bytes (32 MiB) for parsed models and rendered plans or bodies keyed by `(snapshot hash or catalogue_version, chain hash, target, options)`; a plan is identity-independent, so one entry serves every share on the record; it dies with the worker (256 uses or one hour) and never touches KV. Two changes end the "every fleet write expires everything" behaviour: a plugin method `depends_on` returns the set of record ids whose transitive sources include the fleet, with their revisions, and core re-asks only when the index's content hash moves; and `fetch` returns byte-identical raw when the selected rows did not move, so core's hash-extend skips the render. Collections store their members' typed node lists in the snapshot envelope so a collection render never re-parses a member.

Script persistence (`scriptResourceCache`, `$persistentStore`) writes KV from `render`, which is a serve-path method, under a discipline that keeps the serve path cheap: all writes of one render are batched into at most one `kv.put` of the record's single cache document, only when a value changed, and `render` runs at most once per record, target and 30 minutes because of the body cache. This differs from use-count expiry, which would write once per client fetch, and is why one is accepted and the other rejected.

### The line catalogue and identity-rendered entries

A new core-backed read service on vpn-core, `latticenet.vpn-core/lines` method `catalogue`, scope `vpncore:read`, cursor-paginated, credential-free by contract (every template it returns passes the fragment-survival refusal of `srv/line_client_templates.go:82-116`). Per line it returns `line_uuid`, `line_hash_id`, node id and name, node tags, group ids, geo (country, region, city, ASN, provider), machine vendor, region and next renewal, DDNS domains with a verified flag, protocol, transport, security, public host and port, provider edge, the addresses the line's host names resolved to at the last template sync, status, service state, overlay state, a chain block, a probe block, per-identity per-line usage when an identity is named, the client template and its digest, and an `extra` map.

The chain block carries `role` (single, entry, relay, exit), `root`, `downstream_line_uuid`, `path_state` (converged, drifted, busy) and `exit_geo`. For a chain root the template is the composed entry template, credential-free, exactly what `compose` returns today for vless Reality overlays; `path_state` other than converged becomes an exclusion at bind. `exit_geo` is the committed exit line's `NodeGeo`, replaced by the probe's measured exit location when one exists, because `NodeGeo` describes the entry machine and is the wrong answer for a country filter on a relay chain.

The probe block is `verdict`, `at`, `vantage`, `consecutive_failures`, `cold_p50_ms` and `udp_ok`, computed server-side from the design-27 P2 history. This design asks P2 for two things: every Lines-row test records `line_uuid` and template digest beside the config hash, which is the join; and a scheduled sweep under a dedicated system principal with its own rate budget, which is the freshness. Until P2 writes it the block is null; null never excludes, and a predicate over a null block evaluates to unknown, which keep-mode filters treat as not matching and exclusion rules ignore. The consecutive-failure counter is derived from the history on read; the plugin stores nothing about probes.

The request accepts an optional structured selector so the plugin pushes the leading structured filters into the query; the first page also returns `selector_fields`, the set of predicates this server can evaluate, and the plugin's pushdown classifier pushes only those, running any other predicate in the plugin, so a newer plugin and an older server disagree without an error. The catalogue refuses a selector field it does not know. The response carries a canonical `catalogue_version` that doubles as the snapshot's `source_version`.

A fleet record names a selection and a chain, and no identity. `fetch` stores the selected rows as the snapshot. `render` runs the chain over rows carrying placeholders and returns a plan: the ordered lines and, per line, the post-chain node model. A share on a fleet-bound record names the identity it serves (`source.identity_id`, a core share field); preview takes the identity from the operator. Core validates the plan, binds the share's identity per line, applies the exclusion rules identity links already use (`srv/identity_link.go:266` and neighbours) plus the opt-in usage and probe rules, computes the policy userinfo, and calls `convert` with typed nodes. Zero includable lines gives the decoy so clients keep their old nodes. The owner-credential export is never read by new code and leaves the manifest at the final slice.

### Core-backed services the UI needs

The plugin UI can call only what the manifest declares, so every screen that touches core state has a declared service behind it. Beside `latticenet.vpn-core/lines.catalogue`:

- `latticenet.vpn-core/identities.list`: id, name and policy state per identity, credential-free, for the identity pickers.
- `latticenet.sub-store/shares`: today `list`; gains `create`, `update` (display name, remark, icon, tags, default format, update interval, expiry, identity), `rotate`, `set_enabled`, `archive`, `restore`, `purge` and `reorder`. The URL is still revealed only through the step-up reveal gate.
- `latticenet.sub-store/bind`: `preview` runs the validate-and-bind step for a record revision and an identity and returns credential-free entries plus the exclusion list with reasons, which is what the Fleet view and the migration plan view show; `reveal_entry` returns one bound line's URI for one identity under `vpncore:admin` plus the step-up reveal gate, audited, for the node detail and its QR.
- `latticenet.sub-store/plans`: `propose` and `status`, the privileged-change path described under "Security model".

Each service is declared in `host_access`, and each addition is a manifest change signed with the slice that ships it.

### Share serving and tokens

Unchanged in substance, extended in surface. Tokens stay 32-byte CSPRNG values that never enter the plugin. The core share model gains `display_name`, `remark`, `icon` (with colour and fit), `tags`, `order`, `archived_at` and `source.identity_id` beside slug, default format, update interval, enabled, created, rotated and `expires_at`, so shares can be named, filtered, reordered, archived and restored in core. Deleting a record archives its shares; purging them from the recycle bin deletes them. The UI gains duration expiry (a helper over `expires_at`), the exact datetime picker, rotation, a client-rendered QR code from the step-up-revealed URL, and one-tap import links per client (mihomo and Clash, sing-box, Shadowrocket, Stash, Quantumult X, Surge, Loon) built client-side from the revealed URL as app-scheme links that never pass through a third party. Refusals: one decoy for unknown token, slug mismatch, bad format and rate limit; a readable placeholder entry for a known token whose share or identity is in a policy state (disabled, expired, suspended, over quota), exactly as identity links serve one today (`srv/identity_link.go:364-414`). Per-share `age` encryption is implemented in core with `filippo.io/age` on the serve path, where the final body already is; the share stores the recipient public key only; key pairs are generated client-side or revealed once and never stored. Response headers a record may add are an allow-list (`content-disposition`, `profile-update-interval`, `profile-web-page-url`, `plan-name`), bounded in core; `profile-web-page-url` must parse as an `https` URL without userinfo, at most 2 KiB, with a host that is not private; status is never settable; `Subscription-Userinfo` stays canonical-only.

### Sync and publish targets

Artifacts become first-class records: a named job with source, target, options, optional `age` recipient, an optional schedule, a sync flag, a produce-only mode, history (last published, content hash, destination URL) and restore and delete. Core renders an artifact's body through the same path as a share (fetch, render, bind where fleet-bound, convert), encrypts it in core when a recipient is set, and hands the plugin's `publish` the final bytes; `publish` uploads and never renders. Destinations are adapters behind one interface. Two ship: the operator-designated HTTPS destination and Cloudflare R2 over its S3-compatible signed API with the key in the secret store, on the free tier. Both go through `http.operator.do`, bound to the origin captured from the authenticated call. Write methods stay PUT, POST and PATCH; GET and DELETE are admitted only on the two artifact methods `restore` and `delete`, with the same origin binding and a signed 8 MiB response budget on `restore`, so the destination cannot become a proxy for anything but the operator's own artifact store. An HTTPS destination that does not support GET or DELETE reports restore and remote cleanup as unavailable in its destination record. Delete writes a placeholder document at the destination first, then issues DELETE where supported, so a client still polling the old URL sees an empty document and not the last body.

Schedules use a new host call `task.schedule` (capability `task:schedule`): a cron expression, a method and a payload, at most 64 schedules per plugin, a minimum interval of five minutes, one run in flight per schedule, executed by the server's task queue. Three schedule kinds exist: per-artifact, the global sync schedule (sync all, uploads batched per destination) and the produce-only pre-warm schedule. Stable raw URLs on R2 need a custom domain on a Cloudflare zone the operator owns, because the development hostname Cloudflare gives a bucket is rate-limited and not for production; the destination record refuses a raw-URL claim without one. By default the raw URL serves ciphertext, which another Sub-Store instance with the `age` key can consume as a source; a proxy client can read a raw artifact only when the operator opts that artifact into plaintext and accepts the stated consequence that a third-party copy cannot be retracted by rotating a token. Full backup uses the same adapters: upload and download, scheduled or manual, with three encodings (`age` by default, Base64, and plaintext with every secret reference redacted), keep-paths selecting which record paths a backup includes, and a token strategy that chooses whether secret references are carried, dropped or passphrase-wrapped. No Gist or GitLab client, no Worker or cache in front of `/sub/`.

### Storage layout

The single `subscriptions-v1` document is replaced by an index document (ids, kinds, names, display names, tags, revisions, content hashes, manual order, archive flags) plus one document per record (`record-v2-<id>`), one per script program (`script-v2-<id>`), one per artifact, one per archived record, one script cache document per record, and a bounded per-record processing log ring (`log-v2-<id>`, last 50 entries). Deleting a record archives it from the first slice that splits the store, so no deletion is unrecoverable at any point; the recycle bin UI arrives later over the same archive documents. A `kv.delete` host call (server change under `kv:write`) replaces tombstones; the server indexes KV by key instead of scanning the bucket. Secrets (provider URL tokens, `age` secret keys, publish credentials) live only in the encrypted `pluginsecret:` bucket through `secret.put`; records store a reference and a masked tail. Nothing credentialed is written to KV. The per-record ceiling is 4096 nodes with a UI message.

Snapshots use one envelope, `snapshot envelope v2`, with a `version` field and one owner (the store lane of the first engine slice); later slices extend it additively (fleet block, flow block, optimistic cache block) and the reader accepts v1 by re-fetching rather than migrating. The envelope stores the compact canonical model as the render input and retains the provider text beside it, bounded by `MaxSubscriptionRawBytes`, for three stated reasons: `context.raw` for scripts, `$content` for file records, and re-parsing after a parser fix. Fleet snapshots store `line_uuid` sets plus post-pushdown rows and no raw. `MaxSubscriptionRawBytes` rises from 1 MiB to 4 MiB and `MaxSubscriptionRequestBytes` from 4 MiB to 8 MiB in the same server release, because a 4096-node plan with Reality and transport options measures 3 to 4 MB and the `convert` request carries it; the plan and the `convert` request are each bounded at 6 MiB and tested at 4096 nodes.

## The user-script contract

Supported, in the upstream shape so community scripts port without edits:

- Forms: full function (`operator(proxies, targetPlatform, context)`, `filter(...)`, `transformFunction(res, context)`, async allowed) and shortcut body (`$server`, `$res`, `$content`, `$files`, `$options`, `$file` in scope). Full-form "is not defined" falls back to the shortcut form as upstream does.
- `$arguments` from the editor or the link fragment (`#k=v` or URL-encoded JSON).
- `$options` with `_req` (method, path, the allow-listed query parameters the record admits, a bounded header subset) and `_res.headers` restricted to the four allow-listed headers; `_res.status` is ignored with a logged warning.
- `context.source`, `context.env` (Node-like shape without `require`: backend name, version, feature flags), `context.raw` (the retained provider text; for fleet records, the selection rendered as URIs with placeholders), `context.process` enable and disable of later steps by custom name, `targetPlatform`.
- A `ProxyUtils`-compatible helper object: `parse`, `process`, `processResponse`, `produce` (including `produceType: internal`), `yaml`, `Base64`, `b64e`, `b64d`, `getFlag`, `removeFlag`, `getISO`, `isIPv4`, `isIPv6`, `isIP`, `ipAddress`, `getRandomPort`, `isValidUUID`, `hex_md5`, `JSON5`, `age.encrypt`, `age.decrypt`, `age.derivePublicKey`, `doh` (through the invocation's HTTP gateway when network is granted), `DOMAIN_RESOLVERS` read-only, `flowUtils`, a curated `lodash` subset measured by the script corpus, `produceArtifact({name})` over records in the same store with a depth limit of four and a refusal on fleet-bound records.
- `$substore.http` (when granted), `$substore.info` and `$substore.error` into the processing log, `$substore.notify` through the record's notification policy, `$substore.wait`.
- `scriptResourceCache` and `$persistentStore` backed by KV with TTL (default 48 h), 64 KiB per entry, 256 entries per record, written once per render as described under caching.
- Script sources: inline, remote link (fetched over `http.do`, digest-pinned with `hold` and `follow` policies, `noCache` and `insecure` toggles), a stored module, a stored file. Modules are a record kind with create, edit, delete, list and raw fetch.
- Files and mihomo configs: processors with `$content` and `$files`, YAML deep-merge override operators (`key!`, `+key`, `key+`, `<key>`), `main(config)` override scripts, `sourceType` subscription, collection, local, remote or none, proxy-list mode, Add Proxies From Subscription with replace, front and back.
- Inside `convert` (Response Transformers on fleet-bound records): the no-host-call subset listed under "Where scripts run".

Refused, with the reason surfaced in the editor: `require`; runtime globals and the filesystem; `$substore.read` and `$substore.write` over the store (no ambient store; the cache is the only persistence); `downloadFile`; `Gist`; `MMDB` (no database; fleet geo is in the node model); `_res.status` and headers outside the allow-list; network outside `render` and `publish` or outside the record's host allowlist; `external` or exec-shaped proxies created by a script on any record that is not `local` with the explicit opt-in; `produceArtifact` on a fleet-bound record.

Limits: script 512 KiB; 20 s of script time per render shared by all steps, 15 s for any one step, 128 MiB per isolate; 8 HTTP calls per render, 256 KiB per response, 4 MiB total, 5 s per call, 12 s total; 4096 nodes per record; `produceArtifact` depth four; one isolate per invocation, never reused; moving 4096 nodes into and out of an isolate under 150 ms.

## Node filtering

Every upstream filter and operator exists with upstream semantics. The fifteen non-script operators are Quick Setting (udp, tfo, skip-cert-verify, vmess aead, reuse, ecn, block-quic, ip-version, useless, each tri-state), Useless Filter, Region Filter (keep or drop over flag heuristics), Type Filter over the full type list, Regex Filter with `(?i)`, Conditional Filter (AND, OR, NOT over IN, CONTAINS, EQUALS, EXISTS) exposed in the UI and with the `EXISTS` defect fixed, Remove Duplicate Filter, Flag add and remove with the Taiwan choice, Sort (asc, desc, random), Regex Sort with fallback order, Regex Rename with backreferences in the replacement, Regex Delete, Handle Duplicate (delete or rename, fields, digit template, separator, position), Resolve Domain (Google, Cloudflare, Ali, Tencent, custom DoH and HTTP DNS through the guarded HTTP host call in the first release; UDP, TCP and DoT through a server-side `dns.resolve` host call in the final slice; IPv4, IPv6, IP4P; result filters; cache and TTL; timeout; EDNS; concurrency; `no-resolve` honoured) and Add Proxies From Subscription. The three script-facing steps are Script Filter, Script Operator and Response Transformer.

Regex semantics are RE2, by choice. Go `regexp` rejects lookaround (`(?=`, `(?!`, `(?<=`, `(?<!`) and backreferences inside a pattern (`\1`), while backreferences in a Regex Rename replacement work. The editor compiles every pattern on save and refuses one RE2 rejects, with a rewrite offered for the common idiom: a keep-mode Regex Filter whose whole pattern is `^(?!.*(A|B)).*$` is the same as a drop-mode filter on `A|B`, and the editor proposes that edit. At the cutover that moves operators to Go, a migration pass compiles every stored pattern; a record with a pattern RE2 rejects is flagged `regex_incompatible` in the overview, keeps rendering on the fallback bundle until the operator edits it, and after the bundle leaves keeps serving its last good body marked stale with the error visible. No record silently starts serving the decoy, and no backtracking engine is added, because that would reopen the ReDoS surface this row closes.

One operator upstream cannot have: the Structured Filter over fleet metadata. Its predicates are country, region, city, ASN, provider, node tag, group, machine vendor, days until renewal, protocol, transport, security, managed or overlay state, line status, service state, DDNS present, chain role and path state, and probe (`passed within N hours` over `at`, `from vantage V`, `cold p50 under X ms`, `udp ok`). Country, region and city predicates read `exit_geo` for chained lines by default, with a per-step toggle to entry geo. Sort keys include probe cold p50, renewal and usage. The leading run of structured steps is pushed into the catalogue query, and a differential test asserts that any chain gives the same result with and without pushdown over random catalogues. Per-identity usage in the current period is not a filter predicate, because the record names no identity; it is an opt-in exclusion rule core applies at bind. Probe-driven exclusion is per record, off by default, with hysteresis (N consecutive failures, default 3, range 1 to 10) and the decoy when every line fails, because a pass or fail from one vantage says nothing about clients elsewhere (design 27 caveat) and an automatic drop on a probe outage would remove working lines from clients. `service_state == "down"` stays auto-excluded as identity links do today.

## Client targets and the conformance strategy

All 14 targets stay reachable throughout: URI, V2Ray, JSON, sing-box (outbounds and endpoints), ClashMeta and mihomo, Stash, Shadowrocket, Surge, Quantumult X, Loon, Surfboard, Egern, Surge for Mac, legacy Clash. Tier 1 (the first nine) goes native first. Tier 2 (the last five) follows in the order one read of `share_fetch_stats` at the start of the script slice shows per client family; when the statistics show no Tier 2 fetches the default order is Loon, Surfboard, Egern, Surge for Mac, legacy Clash. Surge for Mac's mihomo `external` fallback with its merge options exists for `local` records with an explicit opt-in and for fleet-bound records, where our own producer generates the entry from the typed model with the operator's configured binary path; it is never carried from remote, pasted or script-created content. Target selection stays as today: `?target=` or `?platform=`, then `?format=`, then the record's pin, then the User-Agent class, then URI; legacy `clash` keeps mapping to ClashMeta because a legacy Clash document wiped a client's VLESS and Hysteria2 nodes once.

Conformance is a deliverable, not a test detail. A separate repository, `LatticeNet/lattice-substore-conformance`, fetches upstream at a pinned commit (2.42.3 at the start) when it runs, never commits upstream code, and produces golden outputs over a corpus: a generated protocol by transport by security matrix, every quirk the upstream study names, and synthetic fleet shapes. "Synthetic" means every host, address, SNI, path, short id, key, port and name is replaced by a generated value of the same shape, length and character set, with the protocol mix preserved, so nothing in the corpus describes a real line. The plugin repository holds the corpus inputs and the goldens as data. Three numbers are published per release in the plugin README: parse conformance (fraction of corpus lines whose Go model deep-equals the oracle's parsed node), produce conformance per target (Go output parsed back to structured form with sorted keys and sorted URI queries equal to the oracle; URI and V2Ray additionally byte for byte), and script conformance (100 percent on a named set of community scripts producing the oracle's output; the set is fixed before the script slice starts, only grows, and a script leaves it only with a reviewed reason). The divergence allowlist is closed and has five entries: `external` and exec-shaped entries dropped from non-local input; `_`-prefixed fields stripped on output; `_ca`-style local paths stripped; `require` unresolved in scripts; and `line-safety`, Surge and Quantumult X nodes whose text would break a line rejected (S2 decisions). Extending it is a reviewed change to this design. A target becomes native only at 100 percent; until then the embedded bundle answers it on the isolated path. The harness is proven before it judges Go code by a mutation test (a deliberate one-field change in a producer must be reported) and by one bundle-against-oracle run that records the known 2.36.22 to 2.42.3 divergences. A re-pin of the oracle is a harness change that opens a golden update against the plugin and never a plugin re-sign.

## Security model

Trust boundaries point the same way they do today, and two of them are tightened.

- **Hostile content** (provider feeds, pasted text, remote scripts) is parsed in the plugin, behind the broker's SSRF guard with dial-time and redirect re-checks. The Go normaliser drops `external` and exec-shaped proxies, strips `_` and `_ca` fields, bounds every field, refuses zero-node documents, and is fuzzed (URI, Base64, YAML, Surge, Loon, QX).
- **Scripts** run in a fresh isolate with no filesystem, no ambient store, a shared per-render deadline, a memory cap, network off by default and allow-listed per record, digest-pinned remote links, and an audit line per HTTP call. Checklist row 48 closes in the first slice with tests that the globals are absent, the filesystem is unreachable, a write to the artifact path fails, and no network exists outside an invocation.
- **Fleet credentials** never enter a method that runs scripts or has network: the catalogue is credential-free by contract, the chain runs over placeholders, core validates every planned node against the catalogue before it binds, and `convert` has zero host calls. A script, including a remote one, cannot move a line to a host it controls, because `server` and `port` must be in the line's allowed set and the credential field must carry the untouched placeholder. The owner-credential export leaves the manifest. The selected line set is the plugin's own `fetch` output; core bounds it by the share identity's enabled bindings, not by the record, so a widened selection serves only lines that identity already holds and no credential crosses identities. Narrowing a share below its identity is therefore not an access control, and the share editor says so.
- **Share tokens** never enter the plugin; core owns status, content type, headers, decoy, rate limit, render budget and audit. Response headers from records are allow-listed and bounded in core.
- **Secrets** (provider URL tokens, `age` keys, publish and remote-store credentials) live in the encrypted secret bucket, are shown as host plus masked tail, are revealed only through the plugin's `reveal` method under `substore:admin` plus the existing step-up reveal gate, once per call, audited through `log.write` and the core audit event, never cached by the UI, are redacted from errors, logs and panic messages, and are omitted or passphrase-wrapped on export.
- **Fetch proxies.** When `http.do` dials through an operator-configured proxy, the broker resolves the final target itself, applies the private-address policy to every resolved address, and sends the checked address in the CONNECT request, so the proxy cannot be used to reach a private target by name; a proxy whose own address is private needs an explicit operator allowlist entry.
- **Privileged actions** ride plan, approve, apply. A change is privileged when it alters what an existing token holder on a fleet-bound share receives: editing the selection or chain of a fleet-bound record that has live shares, changing a share's identity, re-binding a legacy record, deleting a fleet-bound record with live shares, and rotating or disabling a share. Record edits save a staged revision; publishing it to live shares goes through `latticenet.sub-store/plans.propose`, which returns the per-share diff (lines added, removed and excluded, per identity) that core shows and hashes; on approval core calls the plugin's `apply_revision`. A record with no live fleet-bound shares publishes immediately. Provider-only edits are audited and not privileged.
- **Supply chain.** No third-party JavaScript in the artifact at the end state; a third-party notice while the fallback bundle ships; the bundle is never re-pinned again; `govulncheck`, `gofmt`, `go vet` in CI; the server verifies the artifact digest whenever a worker starts.
- **Scopes.** Read methods `substore:read`, writes and anything naming a fetch target `substore:admin`; the test that fails if a network-granted method is not admin-scoped stays; every host-call budget is pinned by a counting test.
- **Cloudflare.** R2 holds ciphertext by default. Nothing fronts `/sub/`; a cache or Worker there would blind the decoy, the render budget and the fetch audit. Terminating TLS for `/sub/` at Cloudflare is a trust placement the operator decides outside this design.

## Performance targets

Two kinds of gate, because wall-clock numbers on shared runners are not deterministic. Deterministic gates fail CI: host-call counts (design 18 D7e), `testing.AllocsPerRun` bounds, document sizes and memory ceilings measured in-process. Wall-clock targets are Go benchmarks run with `-count 10` on a GitHub-hosted `ubuntu-24.04` standard runner, compared with benchstat against the recorded baseline for that runner class; the median must stay inside the target and a regression beyond 1.5 times the baseline fails. Memory means the plugin worker's resident set as read from `VmRSS` by a harness that starts the worker binary, with Go `HeapInuse` as the deterministic companion gate; wazero linear memory counts in RSS, so the memory targets apply to scriptless renders, and a script render may add one isolate (up to 128 MiB) on top. End-to-end latency is measured by a server integration test that starts the plugin under the real runner and times a cache-miss `GET /sub/...`. Provider fetch is measured against a local `httptest` provider.

| 4096 nodes, same chain | under 100 ms | benchmark plus allocation bound |

Pool size stays at one worker plus one overflow until the warm runtime is gone, then two plus one. The host HTTP response cap becomes a signed per-method budget: 8 MiB for the subscription service's `fetch` and for artifact `restore`, 256 KiB for script HTTP and `publish`.

## UI and UX

Information architecture, derived from the jobs operators come to do: Overview (what is published, what is stale, what failed, what expires, what is flagged for regex or script changes), Records (one table over subscriptions, collections, files, modules and artifacts with a kind filter; columns published state, nodes in, nodes out, steps, expiry, traffic, last fetch), Fleet (identities and the lines each one would receive through each record, with exclusion reasons, from `bind.preview`), Shares (every share with identity, QR, one-tap import links, expiry, rotation, fetch counts, filter and archive), Logs (processing log with keyword, regex and case search, and clear per record or all), Settings (defaults, locale, notification policy, destinations, schedules). A command palette is the first-class entry on desktop.

Main flows. Create a fleet record: build the selection from structured filters with a live count and a map of what each filter removed, add operators, preview for a chosen identity per target with a per-step delta, create a share for an identity. Add a provider: paste one or more URLs (tokens masked at once, moved to the secret store on save), set fragment options as fields rather than a URL fragment, see the first fetch and its flow info. Build a chain: drag to reorder or move with the keyboard, enable and disable, custom names, copy and paste steps between records, each step showing nodes in and out. Preview and compare: original versus processed with removed and renamed nodes marked, per-target document with copy. Share: create with duration or datetime expiry for an identity, reveal once through step-up, QR rendered client-side, one-tap import, rotate, disable, archive. Publish: artifact to a destination with history. Migrate: an existing owner-credential record shows a warning and a one-click path to re-bind it through a plan.

Desktop at 1440 is the editor's home; 375 is a hard floor, not a mode: the record table collapses to rows with the four state columns, shares and QR, preview and the overview must work on a phone, and the chain editor stays usable. Locale: zh-CN default following the host, en and ru in the same message table, no hard-coded strings. Theme follows the host's tokens (light and dark) with local fallbacks; there is no separate theme picker. The record table has a density toggle (compact rows, or expanded rows with icon and remark), which is the equivalent of upstream's simple and card list modes, plus tag grouping. Every control has a keyboard path, drag reorder included (move up and down with announcements), and the Playwright suite runs axe on every screen. Every surface is rendered and driven with realistic content and the full state set (loading, empty, error, stale, disabled, expired, flagged, long names) before a slice ships, then reviewed. Every UI action maps to a plugin method or a declared core-backed service with the same scope, so an agent can do what a hand does.

## Migration

Share links never change: tokens and slugs are core-owned and the plugin's record ids are stable. Existing subscription, collection and file records move from the single document to the index-plus-records layout in one idempotent migration on first start of the new plugin, with the old document kept until the index verifies. The same pass compiles every stored regex and flags incompatible ones as described under "Node filtering". Existing records keep rendering through the fallback bundle for any target whose Go producer is not yet native, as a whole-chain fallback: the chain compiler marks each step and the target as native or not, and until the script slice a record with any non-native step or target renders entirely on the bundle's isolated path, so Resolve Domain before its Go resolver and scripts before the shim both keep working with no mixed handoff. From the script slice on, the only bundle use is `produce` for a target without a native producer, fed the typed node list the Go chain produced. A native producer takes over a target only after it passes the conformance gate, and the UI offers a per-record diff between the fallback and the native output before cutover of a record whose output changed in names, order or flags (the change clients would notice in proxy groups). Snapshot-render parity is a standing test.

Existing fleet records built from the owner-credential export keep serving under a visible "still serving line owner credentials" warning until the operator re-binds each one through a reviewed plan. A legacy `vpn-core` record becomes a fleet record with the equivalent selection, and each of its shares is given the identity the record named; a legacy `vpn-core-graph` record becomes a fleet record whose selection pins its chain roots in their committed order through the selector's explicit `line_uuid` list, with the catalogue's composed entry template standing in for `compose`. The plan shows, per share, which lines the identity would receive and which are excluded and why. When the last such record is re-bound, the final slice removes the legacy host access. Whether legacy proxy-user records still exist is a fact fetched during that migration, not a design dependency.

## Licensing

Upstream Sub-Store is AGPL-3.0; the plugin repository is MIT and today ships the minified upstream bundle inside its signed artifact without a notice. The end state is a Go implementation of upstream's behaviour with zero upstream JavaScript in the plugin repository or artifact, verified by CI, and written so that the result is not a translation of upstream code. For the two components where a translation would be the natural shortcut, the parser and normaliser and the producers, the work is split: specification writers read upstream and write a per-component behaviour specification plus goldens into the conformance repository; implementers read only the specification, the upstream study and the goldens, and the slices point them at the specification, not at upstream files. Operators and filters are implemented from the upstream study's inventory, which describes behaviour. The shim reproduces an API surface by name, which is interface compatibility. The conformance harness runs upstream as a black box. A CI digest check catches verbatim copies and nothing more; the process above is what makes the claim. Until the bundle leaves, the repository carries a third-party notice naming the bundle, its commit and source, and the bundle is never re-pinned. The interim posture and the reimplementation posture are the two decisions in this design the operator should acknowledge explicitly, because the exposure is the organisation's.

## Slices

Seven slices, each independently shippable behind the unchanged `fetch`, `render`, `convert` contracts, each sized for one workflow of about ten agents. S0 closes the sandbox on the current plugin and lands the platform wave (catalogue, identities list, share model fields, contract extensions, `kv.delete`, `task.schedule`, per-method budgets, cache sizing, raw and request bounds) plus the conformance harness. S1 lands the Go model, parsers, operators, the store split with archive-on-delete, the first native producers and the capability wave manifest. S2 lands fleet sources, structured filters, validate-and-bind, `depends_on`, DDNS, chain and probe fields, the migration path, and removes the warm runtime. S3 lands the script isolate, shim, modules, files and mihomo configs. S4 lands source ergonomics, flow info, secrets, notifications and Resolve Domain. S5 lands shares, artifacts, backup, the recycle bin UI, logs, settings and the operator surface. S6 removes the bundle and the legacy paths and publishes the conformance numbers. Signings: the hotfix is a digest-only re-sign; the vpn-core manifest is signed once at S0; the plugin manifest changes in every slice from S1 to S6, because each adds methods or services whose budgets and scopes are signed per method, so the programme has six manifest-changing plugin signings. Pre-declaring every future method in one wave would cut that to one but would sign unimplemented surface, and is rejected. The ordered plan with lanes, contracts, acceptance tests and checklist coverage is the companion slice document.

### S0 scope as landed (2026-10-09)

An acceptance audit of S0 against its slice plan moved four items to the slice that gives them a surface or a dependency, and recorded the deviations below.

- The opt-in usage and probe exclusion rules, with their hysteresis, move to S2 with the structured filters that let an operator opt in. The probe rule also needs design 27's P2 results history, which does not exist yet, so the catalogue's probe block stays null until P2 writes it.
- Age encryption on the artifact render path lands with artifacts in S5. S0 ships the shared encrypt function and the share serve path, placeholders included.
- The stdio host frame stays at 4 MiB until S1 raises it on the SDK, the server and the plugin together. Until then an HTTP body that reaches a plugin is limited to about 3 MiB after base64, below both the 8 MiB fetch budget and the 4 MiB raw subscription bound.
- The conformance harness opens no golden-update pull request against the plugin yet, because that needs a token that can write to a second repository. A re-pin runs the harness and the goldens are moved by hand until such a token exists.
- The sandbox hotfix differs from the plan in three recorded ways. The guest root is a path that does not exist and cannot be created, rather than an empty mode-0500 directory, so nothing exists to be written. The native `qjs:std` and `qjs:os` modules stay registered: their globals are deleted, but a dynamic import still resolves and its file and environment calls return null or an error code instead of throwing, which reaches nothing either way. The timer globals are kept rather than replaced with an engine-controlled `setTimeout`, because user scripts run only on per-call runtimes that are discarded after the call. The embedded core also swallows a Script Operator's error and passes its nodes through unchanged, so a failing script is not reported; the native chain compiler reports a failed step instead.
- The hotfix and its proof-of-concept test reached the public repository shortly before the fixed release was installed, because the release bundle is built by CI from pushed code. A future security fix to a public plugin repository is built and signed from a local commit, installed, and pushed afterwards.
- The capability-wave manifest is prepared in S1, with the binary that serves it, not in S0. The vpn-core manifest that declares the line catalogue and the identity list is S0's one plugin signing, after the server release that serves them.
- Deviation: `task.schedule` runs call the plugin method directly on the runtime service path, not through the operator task queue, so a scheduled method never runs under an operator's principal or borrows an operator's scopes. The 64-schedule limit, the five-minute floor and one run in flight per schedule id hold as specified.

### S1 decisions (2026-10-09)

- The divergence allowlist gains one normalise kind, `drop_entries_with_keys`, and the `external` entry gains a second step with it. Rule H3 drops a node of any type that carries `exec`, `args`, `local-port`, `local-address` or `local_address`, and the schema could match a field's value but not a key's presence, so two hostile corpus cases could never pass for an implementation of H3. The list stays closed at four entries (the S1 count; the S2 decisions below add a fifth). The new kind applies only at parse stage, where every array element is a node, and may not name a node identity key or a document container, so one entry still cannot hide a whole node list or document. This is the reviewed extension the conformance section requires.
- The S1 host frame raise depends on an SDK fix found while building it: the SDK refused every invoke frame over 1 MiB whatever limit the runtime set, and the worker then exited, so a render whose request passed 1 MiB failed on the current plugin as well (`PROGRAM.md` KI-24). The SDK now bounds a frame by the runtime's own limit, and the plugin picks the fix up with its S1 SDK pin.
- The UI lane merges the three record tables (sources, combinations, files) into one Records table with a kind filter; the plan's "card list" did not exist. String extraction for zh-CN, en and ru touches every screen, so it runs as its own lane after the table lands, and the Playwright and axe gate runs in English first and in all three locales once the strings move.
- The 0.17.0-alpha.1 manifest is least privilege rather than the capability wave the S1 plan prepared. The plan declared six more capabilities (secret, log, notify, task) and five host-access grants that S1 code never calls, on the grounds that the wave is signed once; every slice ships a new binary and is signed again, so that saves nothing and leaves a compromised plugin process with more than it needs. The S1 manifest declares what the binary calls (rpc.call to vpn-core's nodes and subscription sources, http, kv) and the methods its UI binds; each later slice adds the grants its code starts to use.
- Plugins keep building with Go 1.26.4 until their next signed release: a symbol-level `govulncheck` against that toolchain finds no reachable standard library advisory in any of the four plugins, which talk to the host over stdio. Each moves to the server's Go version when it is next signed, sub-store first with S1.

### S2 decisions (2026-10-10)

- The divergence allowlist gains a fifth entry, `line-safety`, and the conformance harness a produce-stage step for it. Upstream writes node text into Surge and Quantumult X lines as it is, so a name, password, path or key holding a line break lets a provider feed add lines to the profile the client imports, a `[Script]`, `[Rule]` or `[MITM]` section among them. That is the line-format counterpart of rule H3, so the native producers reject a node whose entry would hold a control character, U+2028 or U+2029, and the Surge module header drops those characters from the subscription name. Two corpus cases already carried the injection in their goldens (`clash-socks5-name-newline` and `clash-ssh`, an inline PEM key), and no safe output can match them. No value normalisation can express the divergence, because the injected lines cannot be traced back to the node that wrote them, so the entry's one step, `without_line_breaking_nodes`, changes no value: a failing case may match a second golden that regen writes from the oracle for the input without the line-breaking nodes. The step is produce-only and names its line-based targets and its cases, and it matches those cases by exact id, never as prefixes, so a later case whose id starts with `clash-ssh` gets no line-safe golden until a reviewed change names it. The harness self-test proves the entry hides neither a different dropped node, nor a case it does not name, nor a valid node dropped from a case under a named id's prefix. Rejected: keeping upstream's output, which leaves the injection in every native Surge and Quantumult X document, and holding the two misses in plugin-side exception lists, which would be a second allowlist outside the closed one.
- The new rejection is inert in production until Surge and Quantumult X are routed. The plugin's `routed` set holds URI, V2Ray, JSON, ClashMeta and sing-box, so the embedded upstream bundle still answers Surge and Quantumult X, injection included, until the change that adds them to `routed`. To revert the entry, change three repositories together. In the harness: the entry in `allowlist/divergences.yaml`, `MAX_ENTRIES` back to four, the `without_line_breaking_nodes` step in `oracle/lib/allowlist.mjs`, `check.mjs` and `regen.mjs`, the four line-safe goldens, the "Line safety" sections of the Surge and Quantumult X specifications and the allowlist rows of the URI, ClashMeta and sing-box ones, and the self-test and unit-test cases. In the plugin: the vendored harness, the line checks in `surge.go` and `quantumultx.go` with their tests, the line-safe comparison in the Go corpus tests, and `line-safety` in `conformance.json`. Here: this decision and the five-entry count in the conformance section. The producer change is part of the revert, because with the checks kept and the entry gone Surge and Quantumult X match 609 and 610 of 611 and cannot become native; removing the checks brings the injection back, so a revert needs another defence first.
- URI and V2Ray carry the same flaw on a path that is live now, and this entry does not cover it. Their native producers are routed and serve subscriptions, and in those formats a line is a whole proxy link, so a line break in a field written raw lets a provider feed append an `ss://` or `trojan://` link of its own to the operator's served subscription. A provider can already add nodes to its own feed, but an injected link was never a node, so it skips the normaliser's hostile-content rules and every operator the record runs. A review probe of the native URI producer on 2026-10-10 (about 504,000 mutations) found raw line breaks reaching the output through the socks5 name, port and server; the trojan password and server; the vmess and vless uuid and server; the ss port and server; hysteria's auth-str, obfs, ports, sni, up and down; the anytls password and server; tuic's congestion-controller; the wireguard server; and the walked field keys of hysteria, tuic, anytls and wireguard. `uri.md` pins upstream's newline split, so the byte-exact goldens require it today. The fix is a follow-up opened on 2026-10-10 against plugin PR #87, as its own reviewed change to this design: the URI writer rejects a node whose finished line holds a line-breaking character, V2Ray reuses it and drops the node from its join instead of leaving an empty line, and `line-safety` extends to `uri` and `v2ray` with byte-level line-safe goldens and exact case ids. Until it lands, both gaps are live: URI and V2Ray through the native producers, Surge and Quantumult X through the bundle.
